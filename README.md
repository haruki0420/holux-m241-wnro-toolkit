# Holux M-241 の日付が 19.6 年ずれる問題を直す

M-241 が記録する日付が 2026 年なのに 2007 年になるなら、このツールで直せます。
Windows 11 の実機で、バックアップの取得から書き込み、書き込み後の日付確認まで
通しで確認済みです。Linux と macOS は実機では試していません（コードは CI で動きます）。

時刻（hhmmss）はもともと正しく、日付だけが 7168 日（19.6 年）ずれます。原因は
GPS の週番号が 2019 年 4 月に一周したことで、2006 年製のファームがその周回を
計算に入れていません。詳しくは[症状と原因](docs/user/01-symptoms.md)。

やることは 3 つです。ファームを PC に吸い出す（dump）、PC 上で日付定数を書き換える（patch）、
書き戻す（flash）。吸い出しと書き換えは安全で、危ないのは書き戻しだけです。

## 直るもの、直らないもの

| 直るもの | 状態 |
|---|---|
| NMEA の日付（地図アプリや gpsd が見る値） | 実機で確認済み |
| 以後に記録するログの日時 | 未検証（NMEA と同じ計算経路という推測。書き換え後のログは未取得） |
| OLED の日付表示 | 未検証（同じ計算経路なので直るはずだが、画面は未確認） |

| 直らないもの | 理由 |
|---|---|
| パッチ前に記録した既存ログ | 記録済みの値は変わりません。後処理で補正できます |
| 2038 年 11 月（次回ロールオーバー）以降 | この修正は 1 回分ずらすだけなので、また一周すると再発します |
| 日付以外の不具合（電池、ボタン、Bluetooth） | WNRO とは関係ありません |

## インストール

`m241` コマンド 1 つだけです。Python のパッケージとして入ります。

```bash
pip install "git+https://github.com/haruki0420/holux-m241-wnro-toolkit.git"
m241 --help
```

デーモンも GUI も常駐ソフトもありません。アンインストールは
`pip uninstall m241-wnro-toolkit` です。

Python 3.10 以上が必要です。依存は `pyserial` だけで、それ以外は標準ライブラリです。
リポジトリの clone は要りません。

実機をつながずに動作を確かめたいときは `m241 selftest` を実行してください。
同梱のシミュレータで、ファームの読み出し、パッチ、書き戻し、ログの変換、NMEA の日付補正まで
6 段階を通しで試します。

## 用意するもの

| 要るもの | 補足 |
|---|---|
| M-241 本体 | 電源が入り、USB で PC につながること |
| USB ケーブル | 付属のもの |
| PC | Windows 11（実機検証済み）。Windows 10 と Linux / macOS は未検証 |
| `DA_v3.8.4.bin` | **ファームを書き換えるときだけ必要**。下で説明します |

### `DA_v3.8.4.bin` について

ファームの書き込みには `DA_v3.8.4.bin` という小さなプログラムが要ります。
純正の `HoluxLoggerUtility` に同梱されていたもので、**このリポジトリには含めていません**
（権利上、再配布できないため）。このファイルがないとファームの書き込みはできません。

Holux は 2019 年に GPS 事業から撤退しているので、古い配布物は自分で入手する必要があります。
入手したら、このツールで中身を検証できます。

```bash
m241 doctor --from-drop <入手したファイルのあるフォルダ> --extract-to vendor/
```

**書き換えをしない場合、このファイルは不要です。** ログの取り出し、変換、
写真への位置情報付与、地図アプリ用の日付補正は、これなしで動きます。

## 手順

各ステップの成功・失敗の見分け方と所要時間は
[ファームを書き換える](docs/user/03-fix-firmware.md) にまとめてあります。
ここでは流れだけ示します。

### 1. つながるか確認する

```bash
m241 ports   # ケーブルが見えるか
m241 info    # ファームの版と型番
```

`m241 info` が `B-core_1.20, 0043, 01017-00F` のような値を返せば、PC と M-241 は
正しくつながっています。うまくいかないときは `m241 doctor` で環境を確認してください。

### 2. バックアップを取る（読み取りのみ・安全）

```bash
m241 dump auto -o backup/stock.bin
```

ファーム全体（約 400 KB）を PC に保存します。**本体には書き込みません。**
2 回読んでハッシュが一致することを自動で確認します。1 回目のあと電源の入れ直しを
求められるので、電池を抜いて 10 秒待ち、入れ直してから Enter を押します。

### 3. 修正版を作る（PC 内で完結）

```bash
m241 patch backup/stock.bin -o backup/fixed.bin --dry-run   # 何が変わるか確認
m241 patch backup/stock.bin -o backup/fixed.bin             # 実行
```

4 バイトの日付定数を置き換えます。実際に値が変わるのは 3 バイトです
（実機の V1.13 では `0x402F6`、`0x402F7`、`0x59C2C`）。

### 4. 書き戻す（ここだけ危険）

```bash
m241 flash auto --da vendor/DA_v3.8.4.bin --fw backup/fixed.bin --backup backup/stock.bin
```

確認のため `WRITE` と入力すると書き込みが始まります。書き込みが終わると、
ツールはダウンロードエージェントを再起動して結果を表示します。
**読み戻しての照合は行いません。** 成功したかどうかは、電源を入れ直したあとに
NMEA の日付が今日になっているかで確認します（手順 5）。

失敗したときの復旧は[失敗したとき](docs/user/04-recovery.md) に書いてあります。
BootROM はマスク ROM なので消せず、たいていは自分のバックアップを書き戻せば復旧できます。
ただし、間違ったイメージを書いた場合や、書き込み中に電源が落ちた場合は、
本体が使えなくなることがあります。

```bash
# 電池を抜いて 10 秒待ち、入れ直してから、元のバックアップを書き戻す
m241 flash auto --da vendor/DA_v3.8.4.bin --fw backup/stock.bin --backup backup/stock.bin
```

### 5. 確認する

```bash
m241 info                                      # 本体が応答するか
m241 nmea proxy auto --offset-days 0 --stdout  # NMEA の日付をそのまま表示（Ctrl-C で終了）
```

`offset-days 0` は補正せずにそのまま表示する指定なので、書き込みが失敗していれば
19.6 年前の日付のまま見えます。`$GPRMC` の 9 番目のフィールドが日付（ddmmyy）です。

## 書き換えないで済ませたいとき

本体の日付は直りませんが、実害は減らせます。

| 方法 | ログの日付 | 地図アプリの日付 | OLED |
|---|---|---|---|
| 吸い出したログを後処理で補正 | 直る | — | 直らない |
| リアルタイムで日付を補正して中継 | 直る | 直る | 直らない |
| ファームを書き換える | 直る | 直る | 未検証 |

```bash
# ログを吸い出してから後処理で補正
m241 logs download auto -o backup/track.bin
m241 logs read backup/track.bin --format gpx --utc-offset-days 7168 -o track.gpx

# 地図アプリに渡す日付をリアルタイム補正
m241 nmea proxy auto --tcp 127.0.0.1:10110
```

`m241 --help` でも各コマンドの引数を確認できます。

## 対応環境

| | 状態 |
|---|---|
| **Windows 11** | **実機で検証済み**。CP210x ドライバが必要。Windows 10 は未検証 |
| **Linux** | **実機未検証**。`/dev/ttyUSB0`、`dialout` グループに追加 |
| **macOS** | **実機未検証**。`/dev/tty.usbserial-*` |
| Python | 3.10 / 3.11 / 3.12 / 3.13（CI: Linux 3.10・3.11・3.13 / Windows 3.12 / macOS 3.12） |

Windows 以外は、コードが CI で動くことだけ確認しています。実機接続の報告を歓迎します。

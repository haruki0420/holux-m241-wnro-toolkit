# 書き込みに失敗したとき

**落ち着いてください。ほとんどの場合、復旧できます。**

M-241 のチップには **BootROM** という、書き換えられない領域に小さなプログラムが入っています。
ファームの書き込みに失敗しても、この BootROM は消えません。だから電源を入れ直せば
「書き込みを受け付ける状態」で起動します。

---

## まず確認すること

### 本体の電源は入っていますか

電池が入っていて、電源スイッチが ON か確認してください。

### OLED に何か表示されますか

| 表示 | 意味 | 対処 |
|---|---|---|
| 普通に起動した（日付が 2007年） | 書き込みは失敗したが、元のファームは無事 | 手順4をやり直す |
| 何も表示されない | 書き込み途中で止まった | 下の「復旧手順」へ |
| 文字化け・異常表示 | 書き込みが不完全 | 下の「復旧手順」へ |

### PC から見えますか

```bash
m241 ports
```

COM ポートが出なければケーブルの問題です。挿し直してください。

---

## 復旧手順

### ステップ 1 — 電源を完全に切る

1. 電池を抜く
2. **10秒以上待つ**
3. 電池を入れ直す
4. 電源を ON

これで BootROM が待機状態になります。

### ステップ 2 — もう一度書き込む

**元のファーム（バックアップ）を書き戻します。**

```bash
m241 flash auto --da vendor/DA_v3.8.4.bin \
    --fw backup/stock.bin --backup backup/stock.bin
```

`--fw` と `--backup` に**同じファイル**を指定するのがポイントです。
このツールは「バックアップと違う部分があるイメージ」しか受け付けませんが、
同一ファイルなら差分ゼロなので通ります。

**成功の見分け方:** `一致しました` が出て、本体が起動する。

### ステップ 3 — それでもダメなら

本体が NMEA も出さず、書き込みも受け付けない場合:

```bash
m241 dump auto -o /tmp/test.bin --assume-brom
```

`--assume-brom` は「すでに書き込み待機状態のはず」と仮定して接続を試みます。

これで読めたら、ステップ 2 に戻ってください。

### ステップ 4 — 完全に無反応な場合

NMEA も出ず、`--assume-brom` でも応答が無い場合、**ソフトウェアからできることはありません。**

- 電池を抜いて **30秒以上** 待つ
- USB ケーブルを別のポートに挿す
- それでもダメなら、本体のハードウェア的な問題の可能性があります

---

## なぜ復旧できるのか

```
チップ内部
┌─────────────────────────────┐
│ BootROM（書き換え不可）      │ ← 絶対に消えない
│  「書き込みを受け付ける」     │
├─────────────────────────────┤
│ ファーム（書き換え可能）      │ ← ここが壊れる
│  日付の計算・NMEA出力        │
└─────────────────────────────┘
```

書き込みに失敗するのは**下の段**だけです。上の段が生きている限り、
電源を入れ直せば「書き込み待ち」で起動します。

**これは実機で確認済みです。** 開発中に何度か本体が無反応になりましたが、
すべて電池を抜いて入れ直すことで復旧しました。

---

## 復旧できた後の確認

```bash
m241 info
```

`release` と `model` が出れば復旧成功です。

日付が 2007年のままなら、ファームは元に戻ったが修正は適用されていない状態です。
[手順](03-fix-firmware.md) をもう一度最初からやり直してください。

---

## それでも解決しない場合

以下を添えて issue を立ててください。

```bash
m241 doctor
m241 info
```

- 本体の型番（OLED または本体裏の刻印）
- どのステップで失敗したか
- 表示されたエラーメッセージ全文
- 試したこと（電池リセット、別ポートなど）

**ファームのダンプファイルは添付しないでください。** 個人の位置情報が含まれる場合があります。

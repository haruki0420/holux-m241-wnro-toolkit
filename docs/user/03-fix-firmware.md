# ファームを書き換えて日付を直す

このページは実際の手順です。所要時間は **15〜20分**、うち書き込みは **2〜3分**です。

> **先に読んでください:** 書き込みは失敗すると本体が起動しなくなります。
> ただし復旧できる可能性が高いです（[失敗したとき](04-recovery.md)）。
> 心配な場合は [書き換えずに済ませる方法](01-symptoms.md) もあります。

---

## 何が変わるのか

ファーム全体（約 400 KB）のうち、**4 バイトだけ**が変わります。

| 場所 | 変更前 | 変更後 | 意味 |
|---|---|---|---|
| `0x402F4` | `315964800` | `935280000` | 日付の基準時刻を 1024 週ぶん進める |
| `0x59C2C` | `V1.13` | `V1.14` | 改造済みの印 |

これ以外は 1 バイトも変わりません。書き込み後に全バイトを読み戻して照合します。

---

## 用意するもの

| 必要なもの | 確認方法 |
|---|---|
| M-241 本体（電池入り・電源 ON） | OLED に何か表示される |
| USB ケーブル | 付属のもの |
| PC（Windows 10/11） | **実機検証済み**。Linux / macOS は未検証 |
| Python 3.10 以上 | `python --version` |
| `DA_v3.8.4.bin` | 純正 `HoluxLoggerUtility` に同梱。入手方法は [インストール](02-install.md) |

## 手順 1 — デバイスが見えるか確認する

```bash
m241 ports
```

```
COM3  Silicon Labs CP210x USB to UART Bridge
```

**うまくいかない場合:** ケーブルを挿し直す、別の USB ポートを試す、`m241 ports` に何も出なければ CP210x ドライバが入っていません。

次に本体の情報を読みます。

```bash
m241 info
```

```
port     : COM3
release  : B-core_1.20
build    : 0043
model    : 01017-00F
chip     : MT3318
```

**ここで `release` と `model` が出れば、PC と本体は正しくつながっています。**
出ない場合は [トラブルシューティング](06-troubleshooting.md) へ。

---

## 手順 2 — バックアップを取る（読み取りのみ・安全）

```bash
m241 dump auto -o backup/stock.bin
```

```
reading 406,620 bytes ...
sha256: ee52d339205348a53e67fa8990512b594c9a325e7756c2805bf5ce3e020709ae
```

**このステップは本体に一切書き込みません。** 何度失敗しても壊れません。

`m241 dump` は 2 回読んでハッシュが一致することを自動で確認します。
一致しなければエラーになります。

**成功の見分け方:** `sha256:` が表示され、`backup/stock.bin` が約 400 KB になっている。

**所要時間:** 約 40 秒

> **このファイルを消さないでください。** 何かあったときの唯一の復旧元です。

---

## 手順 3 — 修正版を作る（PC 内で完結）

まず何が変わるか確認します。

```bash
m241 patch backup/stock.bin -o backup/fixed.bin --dry-run
```

```
changed offsets: 0x402F6, 0x402F7, 0x59C2C
sha256 before : ee52d339...
sha256 after  : 9f192786...
dry run: nothing was written
```

問題なければ実行します。

```bash
m241 patch backup/stock.bin -o backup/fixed.bin
```

**成功の見分け方:** `backup/fixed.bin` ができ、`sha256 after` が `9f192786...` になっている。

**所要時間:** 1秒

---

## 手順 4 — 書き戻す（ここだけ危険）

```bash
m241 flash auto --da vendor/DA_v3.8.4.bin \
    --fw backup/fixed.bin --backup backup/stock.bin
```

途中で確認を求められます。内容を読んで `WRITE` と入力してください。

```
[1/4] ファームの吸い出しモードに切り替え
[2/4] 書き込み用プログラムを本体のメモリに転送
[3/4] 書き込み範囲を指定（この時点で該当領域が消去されます）
[4/4] データ転送
  0% ... 50% ... 100%
書き込み完了。読み戻して確認します...
  read-back: 9f192786...
  expected : 9f192786...
  一致しました
```

**成功の見分け方:** `一致しました` が出る。

**所要時間:** 2〜3分

> **この間、USB ケーブルを抜かないでください。** 本体を動かさないでください。

**失敗した場合:** [失敗したとき](04-recovery.md) へ。パニックにならないでください。BootROM は消せない領域なので、電源を入れ直せば元に戻ります。

---

## 手順 5 — 確認する

```bash
m241 info
```

日付を確認します。地図アプリを使う場合は次のコマンドで NMEA を見られます。

```bash
m241 nmea proxy auto --tcp 127.0.0.1:10110
```

**成功の見分け方:** NMEA の `$GPRMC` の日付が今日になっている。

```
$GPRMC,093347.000,V,...,151126,,,N*71
                        ^^^^^^ 2026-11-15
```

**実機で確認済み:** 書き込み後、`$GPRMC` の日付が `151126`（2026-11-15）になりました。

---

## 確認できていること・できていないこと

| 項目 | 状態 |
|---|---|
| バックアップ取得（3回、ハッシュ一致） | ✅ 実機で確認済み |
| パッチ適用（4バイト変更） | ✅ 実機で確認済み |
| 書き込み（読み戻しハッシュ一致） | ✅ 実機で確認済み |
| 書き込み後の起動 | ✅ 実機で確認済み |
| NMEA の日付が今日になる | ✅ 実機で確認済み |
| **OLED の日付表示** | ⚠️ 未確認（同じ計算経路なので直るはず） |
| **OLED の `V1.14` 表示** | ⚠️ 未確認 |
| **Linux / macOS での実行** | ⚠️ 未検証 |
